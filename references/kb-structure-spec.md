# `.kb/` Folder Structure Specification

Canonical definition of the knowledge base folder generated by `/kb setup`
in any host repository. All paths are relative to the host repo root.

---

## Full Tree

```
.kb/
│
├── KB_INDEX.md                        ← AI entry point — ALWAYS read this first
│
├── workflows/                         ← One folder per workflow / end-to-end flow
│   └── <workflow-name>/               ← Lowercase, hyphenated (e.g., policy-change)
│       ├── README.md                  ← What + why (product perspective, 1 paragraph)
│       ├── flow.md                    ← Step-by-step execution + mermaid diagram
│       ├── entry-points.md            ← All triggers: REST, Kafka, CLI, cron, gRPC
│       ├── affected-components.md     ← Modules, classes, DB tables, Kafka topics
│       └── edge-cases.md             ← Errors, retries, DLQ, known gotchas
│
├── helpers/                           ← Shared reference data (cross-workflow)
│   │
│   ├── db-tables/
│   │   ├── README.md                  ← Schema overview, DB type, ORM used
│   │   ├── relationships.md           ← FK graph and join patterns
│   │   └── <table-name>.md            ← One file per DB table / entity
│   │
│   ├── kafka/
│   │   ├── topics.md                  ← All topics this service produces + consumes
│   │   └── consumer-groups.md         ← Consumer group config, lag strategy, DLQ
│   │
│   ├── apis/
│   │   ├── README.md                  ← All endpoints this service exposes
│   │   └── <endpoint-name>.md         ← One file per endpoint group / resource
│   │
│   ├── config/
│   │   └── env-vars.md                ← All env vars, feature flags, toggles
│   │
│   └── architecture/
│       ├── overview.md                ← High-level service architecture + diagram
│       ├── data-flow.md               ← Data flow across internal components
│       └── dependencies-map.md        ← Visual map of all inter-service dependencies
│
├── deps/                              ← Cross-repo KB (sub-agent generated)
│   │
│   ├── deps.config.yaml               ← Dep registry: URLs, TTL, extract spec
│   ├── SUB_AGENT_PROTOCOL.md          ← Symlink or copy of references/sub-agent-protocol.md
│   │
│   └── <dep-service-name>/            ← One folder per registered dependency
│       ├── META.md                    ← Freshness: last_fetched, hash, TTL, files list
│       ├── apis/
│       │   └── <tag-or-resource>.md   ← Extracted API docs (filtered by extract spec)
│       ├── kafka/
│       │   └── <topic-name>.md        ← Extracted Kafka schema + notes
│       └── contracts/
│           └── <schema-name>.md       ← Extracted proto / OpenAPI / JSON schema
│
└── product/
    ├── PRD.md                         ← Condensed PRD for AI context
    ├── domain-glossary.md             ← Domain-specific terminology
    ├── changelog.md                   ← High-level feature changelog (AI context use)
    └── non-goals.md                   ← Explicit non-goals (scope control for AI)
```

---

## File Naming Conventions

| Entity | Convention | Example |
|---|---|---|
| Workflow folders | `lowercase-hyphenated` | `policy-change/`, `feature-update/` |
| DB table files | `<table_name>.md` (snake_case) | `audit_log.md`, `entity.md` |
| API endpoint files | `<resource-name>.md` (kebab-case) | `charge-api.md`, `user-profile.md` |
| Kafka topic files | `<topic.name>.md` (dots preserved) | `payment.completed.md` |
| Dep service folders | Match the `name` field in `deps.config.yaml` | `payment-service/` |

---

## KB_INDEX.md — Mandatory File

Must always exist. Must always be regenerated after any structural change.
See [../templates/KB_INDEX.md](../templates/KB_INDEX.md) for the blank template.

**The AI reads ONLY this file first. It never browses `.kb/` freely.**

---

## Git Tracking

All `.kb/` files MUST be committed to version control.

Recommended `.gitignore` additions (none — commit everything):
```gitignore
# Do NOT ignore .kb/ — it must be versioned
# The only exception is temp clone directories, which are always in /tmp
```

Recommended commit message convention:
```
chore: [kb] <what changed>

Examples:
  chore: [kb] initialise knowledge base
  chore: [kb] refresh before MR #42
  chore: [kb] add rollback workflow
  chore: [kb] refresh payment-service dep KB
```

---

## Minimum Valid KB

A KB is considered valid (AI can use it) if it has:
- `KB_INDEX.md` ✅
- At least one `workflows/<name>/entry-points.md` ✅
- `deps/deps.config.yaml` ✅ (even if empty)

Everything else is recommended but optional.
